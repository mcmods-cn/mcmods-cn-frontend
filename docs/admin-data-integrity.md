# 后台编辑、翻译建议与待审预览

后台操作仍受服务端既有权限检查约束；按钮状态只防止错误提交，不能代替鉴权。

OSS 配置、通知模板和用户手工权限必须成功读取当前账号/目标的配置后才能保存。
加载失败保留明确错误和重试入口，不提交初始默认值或空权限列表。用户切换后，
上一用户的数据不能解锁新目标的保存按钮，权限节点选中状态按目标重新初始化。
保存请求期间禁止重复提交；角色保存的迟到结果不能覆盖后来选择的另一角色。

界面语言切换只重新展示标签，不重新初始化经济、货币、商店、等级、任务、
审核设置、通知模板及权限默认配置的未保存输入。角色轨道列表更新不覆盖当前
编辑草稿。管理员创建用户成功后立即清空已提交表单；列表刷新失败同时显示
“用户已创建”和刷新错误，不把持久化成功报告成创建失败。

## 本地界面词条与权限翻译建议

界面词条覆写保存在浏览器，禁止持久化的环境使用当前标签页内存回退；它们
不是数据库业务内容的翻译或共享发布。管理员点击 AI 补全才创建任务；构建、
普通页面读取、语言切换不触发 AI。

词条请求记录本地编辑代次和存储快照。处理期间出现人工输入、重置或其他
标签页更新时，整批建议保守地不应用，并提示核对人工修改后重试。编辑再
恢复原文仍是一次新编辑，不能由旧结果覆盖。页面卸载或账号变化后的结果
也不应用。权限词条只补有非空对应源文的缺失字段，并核对编辑代次。

两类建议都检查项目实际的 `{name}` 插值标识，损坏占位符的字段不应用。
这不证明真实供应商翻译质量，也不是完整 ICU、Markdown 或术语语义校验。
任务仍由后端执行，离开页面不会取消服务端任务；浏览器现有任务观察最长
180 秒。本次验证仅使用确定性替代端点，没有实际付费 AI 调用。

## 待审不可变快照

内容审核队列为 Mod、整合包、六类简单项目和项目变更日志提供按需
`GET /api/v1/content-revisions/{revisionId}` 预览，显示加载、失败和手动重试。
前端核对九位公开 ID、`pending` 状态、实体闭集及对应快照字段/嵌套结构。
未知顶层或快照字段导致拒绝展示，不呈现内部字段。正文、HTML、链接和
Markdown 均显示为惰性文本，不自动执行、请求或打开其中的地址。

服务端返回 `{id, entityType, projectId, status, snapshot}`；变更日志的
`projectId` 是所属项目公开 ID，`entityType` 为 `project_changelog`。服务端
以精确项目审核权限验证该不可变修订，全站审核员和项目范围审核员的自审
政策沿用现有规则。普通私有项目详情接口和编辑权限的边界保持兼容。

新预览要求后端对应接口已部署；旧后端拒绝读取时界面显示错误及重试，不
伪造待审正文。上述编辑保护不要求数据库迁移；前端改动仍兼容原保存接口。

## 日志和统计

运行日志轮询在前次请求完成后再等待 2.5 秒，不重叠读取同一游标；切换筛选、
手动刷新或卸载会取消前一轮并拒绝迟到结果。重置由服务端 `resetNeeded`
驱动，追加按日志 ID 去重且保持现有数量上限。每日统计桶按 UTC 展示其
日期，浏览器本地时区不会把 UTC 午夜解释成前一天。

回归命令与结果见 [共享模块审计记录](audit/frontend-shared-20261002.md)。
生产界面 fixture 用例验证 React 操作与恢复，不代替真实后端权限或持久化验收。

后台未解析引用的类型目录读取失败时提供独立重试，仅重读类型目录，保留搜索
输入、引用类型过滤和列表游标；进行中的重试不能重复启动，离开页面取消读取。
About 编辑器更换界面语言只更新标签和错误文案，保留当前内容语言的未保存
草稿。更换内容语言、账号或显式重试仍读取相应版本；读取失败禁止保存，
版本冲突保留输入供管理员核对。上述恢复入口不改变服务端权限或写入契约。

## 会话同步

认证模块为整个浏览器窗口维护一组事件监听和共享的身份读取。多个组件消费
同一会话时，不会各自作废其他组件的读取；账号变化先清空旧身份，再把当前
读取结果发布给所有订阅者。组件卸载会取消订阅，旧请求仍受会话代次检查。
本地退出立即显示空会话，不在退出响应清理 cookie 前重新读取旧账号。
该行为不改变服务端 cookie、撤销或多设备会话策略。

## AI 任务投递恢复

AI 任务日志沿用 `GET /api/v1/admin/ai/tasks`；新的 `delivery_failure` 是可选投递失败声明，包含 `stage: "publish"`、字符串 `deadLetterId` 和服务端判定的 `retryable`。旧后端未返回此字段时保持普通任务列表，不制造可恢复状态。

仅同时具有 `ai.read` 与 `ai.task.enqueue` 的账号可见“重试投递”。任务必须仍为 `queued`，且后端确认尚未开始供应商请求、没有相关用量记录、当前发布死信可以恢复。调用 `POST /api/v1/admin/ai/tasks/{taskUID}/retry-delivery` 后，202 只表示重新加入可靠投递队列，不表示翻译完成。消费者 `failed`、`running`、`retrying` 或已开始/已计费的请求不能在这里重发。权限与最终状态由后端事务重新核验。

按钮同步防重复操作。已接受的同一死信立即锁定，即使随后 GET 刷新失败也提示“已投递但状态未刷新”，不重新提交成功的 POST；保留列表供显式刷新。相同任务产生新的死信身份后可重新显示恢复入口，刷新不会自动重试。切换筛选和离页取消列表请求，迟到响应不替换当前列表。此功能须先部署兼容后端，无新增数据库迁移；测试使用合成任务和受控 HTTP，未向真实 AI 供应商发请求。

更新日志管理按 cursor 与请求代次隔离列表读取：返回上一页会取消尚未完成的下一页请求，迟到响应不能覆盖当前页。读取期间显示加载状态，失败可在保留编辑草稿的情况下重试；界面语言与内容语言草稿仍各自独立。
