# 前端运行与持久化契约

## HTTP 与 cookie 会话

`apiRequest` 接受后端明确返回的 HTTP 204（例如取消项目关注），其他成功状态仍要求 `{ data: ... }` 响应。`cookie-session` 只是客户端已登录状态标识，不能作为 Bearer token 发送；普通 API 与收藏夹整合包下载使用 `credentials: include`。JWT 调用保留 Bearer 兼容性。

本地 `/api/site-logo` 上传路由通过后端 `admin.config.write` 权限检查后才能写盘。cookie 会话只转发 `mcmods_session`，并要求 Origin 与前端服务 origin 完全一致；真实 JWT 调用仍可使用 Bearer。反向代理须保持可信的请求主机/协议配置，不能向此写入路由发送跨域 cookie 请求。

客户端 `/auth/me` 初始化结果带本地身份代次检查；退出、新登录或其他标签页切换身份后，早先请求不得恢复旧账号。退出后的页面不会自动再次初始化会话；新的明确登录事件才恢复初始化。

异步个人资料结果通过 `saveAuth(result, expectedUserID)` 写回，仅当当前全局账号ID和返回账号ID同时匹配预期身份时接受；拒绝返回false，不修改身份、代次、权限版本或跨页广播。条件写回只更新 username/avatarUrl/signature，保留最新会话token、email、roles、rules及两种授权版本。它不取消同身份正在进行的权限刷新；晚返回的 `/me` 应用最新授权，并保留期间已更新的三个资料字段。`isCurrentAuthUser` 同步检查实际全局身份，可在上传/请求前后与卸载检查配合使用；不能只等React提交新账号界面。明确登录不传 expectedUserID，保留原有账号切换语义。服务端会话及对象权限仍由后端校验。

## 严格 CSP 与部署

`proxy.ts` 为每次页面请求生成 nonce。根布局通过 `await connection()` 在真实请求中渲染，使 Next.js 将同一 nonce 加到框架脚本，严格 `script-src` 保持生效。部署时必须同时发布 proxy 与根布局；静态 HTML、ISR/PPR 和无差别缓存页面 HTML 与此 nonce 模式不兼容。SSR 请求数量与资源消耗会增加，需要按实际流量测量，不能从本地测试推断容量。

## UI 语言与覆盖词条

静态界面语言、数据库内容语言和 AI 译文是三个独立机制。静态界面保留现有八语言资源与源语言继承回退，不在构建、页面读取或语言切换时调用 AI。选择保存在浏览器；SSR 默认简体中文，hydration 后读取本地偏好并更新 `html.lang`。现有八种界面语言均为 LTR。

界面覆盖词条仅保存在当前浏览器，尚不是全站服务器配置。只接受已知键、非空字符串以及与源词条相同的 `{identifier}` 参数集合；损坏的存储数据回退到静态词条。插值一次完成并按字面插入参数，参数中的 `$&` 或 `{another}` 不触发替换语法或递归替换。当前 formatter 不支持 ICU 复数/选择规则，CI 词条测试验证的是项目实际支持的 plain formatter。

浏览器禁止存储或容量耗尽时，语言选择在当前页面内存中继续生效；API 修改请求仍携带页面生命周期内稳定的客户端 ID；列表筛选、排序和 URL 更新继续工作，偏好无法持久化到下次访问。

`npm run test -- tests/i18n-resources_core.test.ts` 使用 TypeScript AST 验证维护资源的重复键，并比较八种有效词典的键、空值与占位符。有效键一致不表示每个键已经人工译为对应语言，也不证明语义翻译质量。

## 草稿与导入恢复

自动草稿保存比较最近成功写入的快照，因此编辑后恢复初始值仍会重新保存。提交完成前等待已开始的自动保存，防止迟到保存将已完成草稿重新打开。被 React effect 重放取消的草稿恢复可以重新启动，旧代次不能清除新恢复的执行状态。

mcmods_exporter 上传恢复键由真实账号 ID、项目 ID 和目标版本 ID 组成。cookie 会话必须在身份已就绪后传入账号 ID；没有身份时不能建立共享恢复键。旧版 `exporter:session:*` 记录不会自动恢复或迁移到任意账号。此更改不删除用户现有浏览器数据；受影响用户可以重新选择文件，后台已有导入任务由后端活动任务接口查询。

上传取消必须阻止已经取消的分片上传开始；轮询等待结束后移除 abort 监听。跨账号切换时界面应中止旧请求并重读对应账号的数据，相关控件由身份就绪状态控制。

## 认领证明、审核分页与部分失败

作者认领至少填写证明文字或上传一个有效本人附件，文字输入最多 10,000 UTF-16 单元；服务端以 Unicode 字符计数、校验本人文件和扫描状态。作者认领审核与编辑员申请审核列表每页 50 条，读取后端 total 并提供前后页；审核后越界页移回有效页，页切换和卸载取消旧请求，迟到结果不能覆盖新队列。后端接口保留 items 并新增 total/limit/offset/hasMore（默认 limit=100，最多200）。旧后端没有 total 时仍展示完整列表，不生成虚假分页；先部署前端入口再部署有界后端。所有权限仍由后端检查，翻页按钮没有替代审核权限。

日志策略 PUT 的 `LOG_CLEANUP_FAILED` 表示策略可能已保存而实际清理部分失败。仅在 ApiError 携带 `details.saved=true` 和结构/整数范围合法的 `details.config` 时，界面采用已保存配置并显示明确失败提示，不显示清理成功；错误详情损坏时保留当前输入并显示普通失败。permission audit 日志不可修改/删除与保留策略的冲突须按后端既有策略处理，本界面不绕过审计保护。

应用日志清理仅在启用配置并保存策略时尝试执行；该界面没有启动后台定时清理任务。保留兼容词条键 enableRollingCleanup，但八语言有效词典与界面说明均表述实际的保存时清理，用户操作记录的独立自动保留机制另行管理。
